Stage	What it does
1. AI-assisted synthesis	Agent ingests documents, retrieves unit-specific data, runs first-principles/tool-verified calculations, searches literature/incident databases, and produces a structured draft — every claim cited, every gap explicitly flagged as unresolved rather than assumed
2. Human HAZID workshop	Cross-functional team uses the draft as a starting point, challenges it, adds tacit knowledge, closes the "unknown" flags, and the qualified reviewer signs off


Mapping to your company's PSM framework


The Documentation-Trusting pass — assumes SOPs/P&IDs are accurate and current, builds the hazard picture straight from them.
The Skeptic/Deviation pass — explicitly asked: "assume the as-built unit has drifted from these documents; what modifications, bypasses, or undocumented changes would make this analysis wrong?" This forces the model to reason about document staleness rather than treat text as ground truth.
The Operator's-Eye pass — asked to reason from an operations/field perspective: what would someone running this skid day-to-day worry about that a design document wouldn't capture (manual interventions, sampling habits, known nuisance alarms that get ignored)?
The Cross-Discipline Interaction pass — deliberately looks for hazards at the boundary between disciplines (e.g., a metallurgy issue that only becomes dangerous because of an instrumentation blind spot, or a process change that invalidates a mechanical design assumption).

Then have the agent reconcile conflicts between these passes explicitly in the output — "Pass A assumed X; Pass B flags that X may not hold because Y" — rather than silently averaging them into one confident narrative. Disagreement between passes becomes a feature of the report, not noise to smooth over.
Make "document silence" a first-class finding, not an absence
Most of what a human team catches that documents miss comes from things that were never written down. You can't retrieve what isn't there — but you can get the agent to systematically flag where it should have found something and didn't:
If literature suggests carbonyl formation is plausible for this metallurgy/CO partial pressure/temperature regime but no internal document mentions it → flag as "known hazard class absent from site documentation — possible gap, not confirmation of absence of risk."

Build a structured "challenge sheet" instead of a narrative report

Rather than ending in prose, end each hazard finding with a standing set of challenge questions aimed at the human reviewers,
Finding: Potential Ni(CO)₄ formation during regeneration at [T, P, CO partial pressure].
Evidence: [cites P&ID, SOP step, literature source].
Open questions for the review team: Has this metallurgy been in CO service before at these conditions? Are there field reports of unusual deposits or odors during past regenerations that were never logged as incidents? Does the current catalyst vendor spec match what's assumed in the design basis?

This does two things: it makes clear the AI is not asserting completeness, and it gives the human HAZID team a running start on the specific disagreements/unknowns to interrogate, rather than a generic "please review."

3. Weight the literature/incident search toward analogous failures, not just this unit

A lot of what a human brings is "I saw this happen at a different plant." You can partially replicate this by having the agent's literature/incident search explicitly target near-miss and
 incident reports from structurally similar units (same reaction class, same catalyst family, same phase behavior) rather than
 only searching for this exact skid's history. Tag these as "analogous incident, not site-specific" so reviewers know it's a prompt for discussion, not a confirmed site risk.
 
 Route ambiguous/judgment-heavy findings to explicit human decision points

Some things genuinely require a judgment call that shouldn't be resolved by the agent at all — e.g., "is this deviation credible enough to warrant a scenario." For these, 
don't have the agent decide; have it present the fork and stop:

The Tier 1/2/3 document split matters most for agent behavior design — you want the agent to hard-stop or heavily caveat when Tier 1 is missing, not silently proceed with a thin document set.
The four-pass adversarial synthesis is the mechanism that does the heaviest lifting against your original concern — it's the closest an agent can get to manufactured disagreement.
The "Unresolved / Requires Human Judgment" and "Evidence Gaps Register" sections are structurally load-bearing — they're what the workshop agenda gets built from, not optional appendices.

Value creation — five pillars, each backed by something you can point at

1. It catches document drift before the field does, not after.
Run18's core finding wasn't generated by the AI being clever — it was generated by the AI actually reading four documents (SOP, pre-MOC deck, 2020 HAZOP, user statement) that disagreed with each other by temperature, and refusing to silently pick one. That disagreement existed in your document system before this run was ever proposed. No one had occasion to notice it until someone tried to correlate all four at once. That's the real value: it doesn't invent new hazards, it makes existing, buried inconsistencies visible on a predictable schedule (every time someone proposes new work), instead of waiting for an incident or an alert engineer to stumble on it.

2. It applies literature-grounded screening consistently, every single time — including the checks people forget.
The HTHA example is your best evidence for this. The requester named it as a known concern. The first draft of the report still didn't engage with it by name or method. That's not a hypothetical failure mode — it's what actually happened in this thread. A tool that mechanically runs a fixed checklist against API 941, LFL/UFL tables, and exposure limits every time closes exactly that gap: not because it's smarter than your engineers, but because it doesn't get tired, distracted, or run out of workshop time before it gets to item 14 on the list.

3. It compresses the pre-read, not the judgment.
The expensive human bottleneck isn't the workshop decision — it's the days or weeks someone spends reading SOPs, hunting for the last HAZOP, and figuring out what's changed since the last similar run before the workshop can even be scheduled. That's the part this tool actually replaces. It doesn't touch the two hours where six people argue about whether a deviation is credible — it just means those two hours start from a cited synthesis instead of from someone's memory of what they read last week.

4. It builds a compounding evidence base instead of a one-off document.
Every gap the workshop closes (the actual installed alloy, the real catalyst code, the resolved date format) is now recorded evidence for the next experiment on the same skid. A static checklist doesn't get smarter. This does, if you feed workshop outcomes back into the evidence register — which is a genuine, durable asset most safety programs don't currently have in machine-usable form.

5. It has a narrow, defensible scope, which is itself a selling point.
It explicitly does not approve anything, judge safeguard adequacy, or replace the technical authority. That's not a limitation to apologize for — it's what makes it easy to greenlight. You're not asking anyone to trust an AI with a safety decision; you're asking them to trust it with the reading and cross-checking they'd have delegated to a junior engineer anyway, done more thoroughly and with citations.

The trap is letting people pattern-match it to "AI-powered HAZOP" and then judge it against a 40-year-old, well-understood methodology it was never trying to be. Get ahead of that comparison explicitly.
"This doesn't replace the HAZID workshop or the HAZOP that follows it — it replaces the week someone currently spends reading old SOPs and hoping they didn't miss a document before the workshop starts. It reads faster and more completely than a person can, cites everything it finds, and — critically — it's built to say 'I don't have enough information' instead of guessing. It has no authority to approve anything. It just means the room starts arguing about the real disagreement instead of spending the first two hours discovering that one exists."

name the failure mode where the tool is overtrusted

The failure mode: "silence mistaken for clearance."

The tool is disciplined about not inventing values — when it lacks data, it produces a clean, well-formatted "Gap" or "Insufficient Basis" entry instead of guessing. But that entry sits in the same document, in the same professional tone, right next to thoroughly-cited "Evidenced" findings. A reviewer skimming a long, well-structured, heavily-cited report under time pressure can let the formatting authority of the document stand in for actual completeness — reading "nothing flagged here" as "checked and fine" rather than "not actually assessed." The better the report looks, 
the more this risk grows, because a polished document earns more unearned trust than a rushed human draft would.

"The failure mode we're watching for is someone treating a clean-looking report as a completed safety check. A 'Gap' tag and an 'Evidenced' tag look the same at a glance — same formatting, same confidence in tone — so the real risk isn't the tool being wrong, it's a reviewer not slowing down enough to notice which tag is which. We're mitigating that by requiring the workshop to explicitly walk the Gap and Inferred sections before anything else, not just the findings — and by never letting the tool's output be the final artifact. 
It's always a draft someone signs against."
The mitigation to pair with it (say this in the same breath, don't wait to be asked):

Evidence-tier walkthrough is a mandatory, timed agenda item in the workshop — not optional reading.
No sign-off authority ever sits with the tool's output alone; a named accountable reviewer signs the final version.
Track whether gap-closure actually happens across runs, so an unresolved gap doesn't quietly get treated as "already looked at" the next time the same skid comes up.

That last point is worth naming even if they don't ask — it's the second-order version of the same failure (a gap that's been carried forward several times starts to feel resolved just by repetition), and naming it unprompted signals you're not just patching the obvious version of the problem.


"Before I get into the tool itself, I want to spend thirty seconds on why this is coming up now, because it's not a hypothetical efficiency pitch — it's a direct consequence of decisions we've already made.

We've consolidated our labs. That's reduced the number of capability units we're running — but it hasn't reduced the range of chemistry we're asked to run. So the same skid that used to serve one fairly stable process now has to flex across very different chemistries, often on an ad hoc basis, on short notice.

And every time that flex happens — a new chemistry, a wider operating envelope, a different catalyst — that's not a footnote. That's a fresh management-of-change cycle. Each one needs its own hazard basis prepared from scratch.

So here's the actual math problem: fewer capability units, each one now carrying a broader remit, means MOC frequency is going up — and our manual hazard-review bandwidth hasn't gone up with it. That gap is what's actually driving this conversation. It's not that our current process is bad. It's that we've built an operating model that needs hazard-basis prep to happen faster and more often than one person reading SOPs can keep pace with.

That's the problem this tool is built against."

"So what is this, exactly?

It's a synthesis and calculation-screening agent — not a decision-maker. You give it a short input form and point it at what's already connected: SOPs, P&IDs, prior HAZID and HAZOP work, RHAs, design data, and open literature. It reads all of that, cross-checks it, runs the calculations it can defend with public data, and produces a draft E-HAZID — hazard identification only. It doesn't touch HAZOP worksheets, it doesn't do LOPA, it doesn't judge safeguards or interlocks. And it never approves anything. That line doesn't move, no matter how good the draft looks.

Now — the natural next question in this room is 'okay, so why should I trust what it hands me?' That's fair, and it's worth answering directly rather than asking you to just take it on faith.

Four things. First, it runs four independent passes over the same evidence — one trusting the documents, one actively trying to break that trust, one thinking like an operator, one hunting for cross-discipline blind spots — and when those passes disagree, it shows you the disagreement. It doesn't quietly pick a winner.

Second, every single finding is tagged — evidenced, inferred, or gap — so a well-supported conclusion never reads the same as an educated guess. That distinction stays visible all the way through.

Third, it doesn't invent numbers. If a public constant exists — a flammability limit, an exposure limit, a material standard — it uses it and cites it. If the number has to come from your specific unit and that data isn't there, it says so plainly, instead of filling the gap with something plausible-sounding.

And fourth — it never signs anything. Every run ends at a named human who owns the final call. This tool drafts the basis for that decision. It doesn't make the decision.

That combination is the actual pitch: faster reading, same accountability."
